# M2-2 真实人员排班查询证据（2026-09-19）

## 范围与版本

- 基线提交：`7c48975`（M2-1 商家与草稿）。
- 环境：Windows、Python 3.12.14 项目虚拟环境、Node 24.15.0、npm 11.12.1、PostgreSQL 17.11。
- 本任务完成美容场景 M2-2；没有实现 M3 的候选选择、占位、确认、预约写入或预约编号。
- `docs/PRODUCT.md` 与 `docs/ACCEPTANCE.md` 未修改，没有为当前实现降低原要求。

## 已实现

- 冻结原始 `0001` DDL，新增 `0002_m2_staff_and_availability` 和 `0003_m2_schedule_revision` 增量迁移。
- PostgreSQL 持久化美容师、服务资格、每周工作窗口、服务前后缓冲、查询记录和候选记录。
- 演示排班明确标识：Lisa 可做基础洗护和全套美容，Marco 只可做基础洗护，周日闭店。
- `search_availability` 只接收预期排班修订号；服务、日期、人员和身份全部从受信草稿/服务端上下文读取。
- 查询只要求服务和日期；点名人员时必须先匹配当前商家的真实 `staff_id`，不信任自由文本直接授权。
- 候选包含服务时间和完整忙碌区间，缓冲真正参与是否能放入工作窗口的计算。
- 独立 `availability_revision`：服务、日期、时段、真实人员或人员偏好变化使旧结果失效；姓名、电话等不影响排班的修改不使候选失效。
- 查询在计算完成、持久化之前再次锁定并检查排班修订号；晚到旧查询返回冲突，不能写成当前结果。
- 商家服务、时长、缓冲、时区或人员排班配置使用服务端指纹和版本管理；幂等 seed 不升版，真实配置变化会使旧候选失效。
- 无空档时返回后续真实开放日期；所有时间使用商家 IANA 时区并保留 UTC offset。
- 查询结果可按原 owner/session 重读；跨 session 返回 404；过时结果返回 `stale` 且不再返回候选。
- 前端状态页更新为 M2，另有不打印服务令牌的完整 HTTP 探针。
