## 已实现

- PostgreSQL 初始版本迁移：`merchants`、`merchant_services`、`booking_drafts` 与 `schema_migrations`。
- 可重复执行的演示商家 seed；运行时商家资料改为从 PostgreSQL 读取，不再由接口直接返回静态对象。
- 一个按受信 `merchant_id + owner_id + voice_session_id` 隔离的草稿；网关服务令牌与固定商家绑定继续生效。
- 单一 PATCH 写入口支持一次批量字段、明确纠正、`clear_fields` 清空、遗漏字段保持、同值不升版和乐观版本冲突。
- 服务 ID 必须真实属于当前商家；模型不能在请求正文提供商家/客户/会话身份、来电号码或电话来源。
- 网页场景 `incoming_phone` 保持空；用户主动提供的联系电话单独保存，并由服务端标记 `voice_user_provided`。
- 查询条件与正式提交条件分开返回。M2-1 中即使资料齐全，正式条件仍缺 `selected_availability`，不会伪称能查空档或创建预约。
- 独立 `*_test` PostgreSQL 测试库、一键检查脚本和运行中 HTTP 探针。
