# M4 工具续播、耗时监控与商家资料加固证据（2026-09-20）

## 问题事实与修复

- 失败链路位于实时网关：模型在同一响应中先播报“稍等”并发起函数调用时，已有音频会令工具结果以 `suppressResponse` 结束，因此结果虽已返回，模型却没有后续响应。现将业务工具批次标记为必须续播；工具结束后同一轮只触发一次继续响应，受控预约摘要仍优先走原播放入口。
- 工具生命周期增加 `started/completed/failed/ignored` 事件，终态记录真实 `durationMs`；语音轮次记录用户停说、响应开始、首段音频和响应完成时间。事件不记录客户原话、姓名、电话、工具参数或结果。
- 新增 `npm run report:voice-latency`，只从上述事件计算样本数、最小值、P50、P95 和最大值。没有真实样本时返回 `no_samples`，不把 HTTP 五秒超时伪装成服务承诺，也不让模型自行承诺“三秒/五秒”。
- 日期、服务、时间偏好或人员偏好改变后，旧候选立即失效；没有针对新日期取得具体候选前，网关不向后端发起必败的 prepare。替代日期只表示建议日期，不能冒充具体时段。
- 演示商家资料新增独立的公开营业时间、员工公开介绍与专长，以及幼犬、疫苗、到店、迟到、攻击风险和价格确认规则。公开营业时间不再从单个员工排班推断，服务资格仍以真实 `service_ids` 和排班为准。
