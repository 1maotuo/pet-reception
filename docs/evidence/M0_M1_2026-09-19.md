## 深入真人复测发现的问题

用户随后在全新浏览器身份中进行了更长的自然中文对话。连续语音、播报和多次“已打断”均可观察，但以下 M1 工具行为未通过：

- 清晰询问“这家店叫什么名字、有哪些服务”时，模型反问具体商家，没有使用服务端已经绑定的演示商家。
- 询问基础洗护和全套美容价格时，模型声称资料可能没有价格，没有返回工具中明确存在的演示价格 `$55 起` 和 `$95 起`。
- 该真人会话没有生成新的 Gateway Work；持久任务仍只有此前显式要求“通过可用工具查询”的 2 个完成项。FastAPI 日志也没有该自然语音会话对应的商家资料请求。
- ASR 对部分口语存在错字，但“这家店叫什么名字、有哪些服务”和“只告诉我全套美容价格”足够清晰，因此不能把工具漏调归因于转写错误。
- 用户提到自己身体不舒服时，助手给出了通用就医建议并表示可以查找医疗机构；没有诊断，但“查找人类医疗机构”不在本阶段已实现能力内，属于范围表达不准确。

定位结果：HTTP 工具、身份注入和结果回传本身可用；失败发生在 Realtime 前台决定是否调用 `spawn_thinking` 的路由层。当前项目把产品说明放在 `ASSISTANT.md`，而上游基础 Prompt 明确将该文件标为 `persona_only`，其中涉及工具、路由和能力的文字无效。先前自动化提示显式写了“请通过可用工具”，因此掩盖了自然表达下的路由缺口。

## 商家专属前台与停顿优化复测

用户进一步明确：这不是通用电脑助手；每通电话属于一家店，新连接由店铺前台先问候，全程以本店服务和预约为中心，无关话题应自然回拉；宠物安全分流随商家类型配置；短暂停顿不能立即抢答。

- 新增受信 `config/demo-merchant.json`。后端商家目录和语音网关读取同一商家来源；前台角色、开场白、范围回拉、安全指引和能力开关由服务端注入，不相信模型填写商家或会话身份。
- 项目 Prompt 从通用“可处理电脑工作”改为当前商家预约前台；`spawn_thinking` 只允许用于当前商家公开资料，禁止拿它做电脑操作、新闻、人类医院、空档或预约写入。
- 1.11.0 没有公开首次问候钩子，且 Audio Profile 固定 `smart_turn`。守卫脚本只对锁定的 1.11.0 补入 `initialGreeting`，复用上游响应队列；同时选择千问原生 `server_vad`。初始停顿实验使用 `silence_duration_ms=1200`，用户进一步反馈背景声敏感、慢速分段仍不理想后，调整为 `threshold=0.65`、`silence_duration_ms=1800`。没有创建浏览器 VAD、第二套提交定时器、播放器或重连逻辑。
- 第一次尝试直接调用上游 `speak()` 时，真实千问在空对话返回 `invalid_value: conversation has no messages or no user message`。该失败没有作为通过；实现改为上游已有 `injectResult(..., { injectContext: true })` 后，在全新连接真实播出：“您好，这里是 Paws & Bubbles 宠物美容预约前台……”。
- 真实模型文字联调结果：
  - “你是谁？你能帮我做什么？”回答为 Paws & Bubbles 宠物美容预约前台，只描述本店服务与预约准备，并说明不能查空档/创建预约。
  - 人类不适请求给出人类医疗安全建议后回到本店范围；宠物不适请求建议先联系兽医/宠物急诊，明确当前店只做美容洗护。
  - “基础洗护多少钱？我想约明天下午。”真实创建 Work，同一会话调用 HTTP 工具，返回 `$55 起` 演示价格，并明确未查空档、未创建预约。
  - “查 AI 新闻、操作电脑”被拒绝并自然回到本店洗护美容服务，没有调用商家工具冒充通用能力。
- 最新自动断言实际构造出的 DashScope Session 为 `{"type":"server_vad","threshold":0.65,"silence_duration_ms":1800}`。这个断言只能证明配置进入唯一服务端轮次检测，不能替代真人噪声、停顿、口音和小声表达听感。
- 设备诊断发现浏览器虽然将 `USB Audio Device` 列为默认输入，但上游未指定 `deviceId` 时，实际新建轨道为电脑内置 `麦克风阵列 (Senary Audio)`；这解释了堵住耳机麦克风后仍能收录环境谈话。现通过服务端非密钥配置 `VOICE_AUDIO_INPUT_LABEL=USB Audio Device` 选择物理设备，继续调用上游原有 `getUserMedia()`，不改录音和 VAD 实现。真实浏览器重新授权后，轨道回报 `selectedLabel=麦克风 (USB Audio Device)`；麦克风阵列不再被选中。
- 设备选择自动测试覆盖两条路径：匹配时传入物理 USB 设备的 exact `deviceId`；指定设备不存在时明确失败且不会调用默认录音作为回退。
- 增加慢速、分段、口音/同音字的上下文规则；明显未说完的片段只提示继续，不调用工具。该规则改善对完整上下文的使用，但 ASR 是否正确识别具体口音仍取决于真实音频，不能用文字测试冒充通过。
- 真实浏览器复测“宠物毛长、脏、有异味、性格不好，推荐什么美容”已先创建 Work 并读取正确商家资料，证明自然推荐请求可进入真实工具。不过当前演示目录只有服务名称和价格说明；模型仍自行推荐“全套美容”并推断清洁效果，超出资料字段。工具结果与 Prompt 已明确加入资料边界，但该次模型行为不计通过；M1 不声称已经具备可靠的个性化服务匹配，后续必须以受信服务适用性数据和真人复测为准。
- 本轮最终完整回归通过：后端 5 passed/1 skipped、真实 PostgreSQL 1 passed、依赖检查无冲突、Web 2 passed、Voice 8 passed、Vite 构建与 Compose 配置检查通过。耳机轨道复验页面控制台 0 error。
